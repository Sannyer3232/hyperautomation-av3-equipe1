Tratamento

• Exemplos por equipe:

+ produção atrasada → ocorrência CRÍTICA.

• DOCKER
ü Explicar de forma simples.
• IMAGEM: É o pacote da aplicação.
• CONTAINER: É a imagem funcionando.
• VOLUME: É onde podemos manter dados 
persistentes, como:
ü logs;
ü relatórios;
ü arquivos de saída.
• Fluxo:
Dockerfile
↓
Docker Image
↓
Container
↓
pai.bot.py
↓
Processos 1 → 2 → 3 → 4 → 5
• Na fala: “ O Docker empacota nossa aplicação e 
suas dependências para que ela possa ser 
executada de forma padronizada."

• BUILD E PUBLICAÇÃO NO GHCR
• Depois que os testes passam:
Testes aprovados
↓
Docker Build
↓
Imagem Docker
↓
GHCR
• Importante: Nesta atividade utilizaremos GHCR. 
Não utilizaremos Docker Hub.
• Exemplo conceitual:
GitHub
   ↓
GitHub Actions
   ↓
Docker Build
   ↓
GHCR
   ↓
Imagem publicada• GitHub Container Registry
ü É o registro onde a equipe armazenará 
a imagem Docker.

=== Page 19 ===
DEFESA TÉCNICA — AVALIAÇÃO 3
• LOGS, ALERTAS E MONITORAMENTO
ü Mostrar que a solução possui rastreabilidade.
• O log deve permitir saber:
Data/Hora → Processo → Status → Mensagem
• Severidades:
ü INFO → execução normal;
ü AVISO → inconsistência que precisa de 
atenção;
ü ERRO → falha localizada;
ü CRÍTICO → falha que impede a continuidade.
 Na fala: “ Os logs permitem saber o que 
aconteceu durante a execução e facilitam a 
identificação de problemas."

DEFESA TÉCNICA — AVALIAÇÃO 3
• FALLBACK E CIRCUIT BREAKER
• FALLBACK
ü É uma alternativa quando o caminho 
principal falha.
• Exemplo:
Fonte principal indisponível
↓
Alternativa
↓
Continuação controlada
• CIRCUIT BREAKER
ü É um mecanismo de proteção.
• Exemplo:
Falha 1
  ↓
Falha 2
  ↓
Falha 3
  ↓
CIRCUIT BREAKER
  ↓
PARA NOVAS TENTATIVAS
• Na fala: “ O Circuit Breaker evita que o robô fique 
tentando indefinidamente acessar uma fonte que 
está apresentando falhas."
